+**Pipeline steps**:
+
+1. **Fetch weekly rosters (80 calls).** For each (year, week) in {2020..2024} × {1..16}, call `TYPE=rosters?L=…&W=N&FRANCHISE=&JSON=1&APIKEY=…`. Stage to `/tmp/mfl_rosters_pass3_<year>_W<n>.json`. Each row: `(franchise_id, player_id, salary, contractYear, contractStatus, contractInfo, status)`.
+
+2. **Compute `weeks_active` (transaction-derived, no API).** For each closed cycle in 2020–2024, run a SQL pass: count rows in `nfl_season_calendar` for the cycle's season where the week's Thursday-anchor falls within `[acquisition_date, drop_date]` (ET). +3. **Populate `salary_at_drop_usd` / `tcv_at_drop_usd` / `contract_type_at_acquisition` / GF flag.** For each closed cycle, look up `(franchise_id, player_id)` in the **W = drop_week − 1** snapshot (anchor probe 2026-05-09 confirmed `W=N` reflects end-of-week-N state, so drop_week itself is post-drop). +   - `contract_type_at_acquisition` ← from the locked `contractStatus` mapping (table below). Note: schema only has `contract_type_at_acquisition`, not `contract_type_at_drop`.
