# FCFS contracts — the rule, the failure of 2026-09-20, the fix, the corrections

**What canon said (`league_context_v1.md` §A5, §T1.6, the §A4 acquisition list) — and now says.** An FCFS (first-come, first-serve free agent) acquisition was a **$1K, 1-year WW contract** ("Salary: $1K flat"; "Contract: 1-year WW …"), with no statement of the exact form MFL holds. **Keith's 2026 ruling is now written into canon (§A5, §T1.6 — updated 2026-09-26 on this branch, with the earned-salary rules in §A5 / §D1 / §C3):** the exact form written to MFL is **$1,000 · one year · `Vet-WW` (`Rookie-WW` for an NFL rookie) · `CL 1| TCV 1K| AAV 1K`**. There is no bid and no negotiation, so an FCFS pickup is never a "needs a price from a human" case. **A completed FCFS transaction must never remain blank in MFL or D1.** The rule lives in one place: `worker/src/fcfs_contract.js`.

## 1. What went wrong (Watson 09-13; Franklin, Bourne, Al-Shaair 09-20)

| Question | Answer (evidence) |
|---|---|
| Was the contract-writing function never called? | It **was** called — every 5 minutes. The `*/5` cron runs `add-tracker → stamp-ww-contracts → annotate`; `ADD_TRACKER_ENABLED` and `WW_CONTRACT_STAMP_ENABLED` are both on in `ups_settings 'feature_flags'`; it stamped 15 BBID awards on 09-17. |
| Misclassified? | No. `ups_add_events` recorded all four as `source='fcfs'`, and the stamper's `takeAwards` tagged them `fcfs`. |
| Did the write fail? | No write was attempted. |
| Skipped because no bid existed? | **Yes — the first incorrect write.** `finalizeWaiverContracts` priced every waiver-style award from a bid. An FCFS transaction is `added\|dropped` with no bid field and MFL leaves the salary blank, so every FCFS row fell into `needs_input: no_bid_establishable`. The design comment said "MFL's $1K is not a fallback" — true for a **BBID** bid, wrong for **FCFS**, whose price is fixed. |
| Later overwritten? | No. |
| Marked complete before the write? | The annotator (which runs after the stamp) tried the blank row and wrote `contract_annotated = 3` ("fresh read had no salary/contractYear — refused to annotate") on all four add events: the transaction was closed as *refused*, never completed. |
| Why no retry repaired it? | It retried every tick — and refused identically every tick. A deterministic refusal is not fixed by retrying. |
| Why no alert? | The cron handled `needs_input` as "never a DM … just a durable log line". |
| Side effect | Al-Shaair (0004) was dropped 09-25 with the contract still blank → drop event 141 stored `contract_unstamped_needs_review` (unpriced). |
| A second wrong belief | The annotator route's header claimed MFL's default row makes an FCFS add a $1K / 1-year WW contract "with zero work from us". The default row (`0000`) is blank — corrected in the header. |

## 2. The fix (worker — the first authoritative failure, not a later reconciliation)

`finalizeWaiverContracts` decides an FCFS row with `planFcfsStamp`: detect → resolve player + franchise → canonical contract (no bid) → write through the normal salaries import (full-attribute, `APPEND=1`) → **re-read to verify (with a retry read for a lagging export)** → audit row in `ups_auction_contract_finalizations` under **`source = 'fcfs'`** (so it can never overwrite a BBID stamp's record of the same player) → close `ups_add_events` (`contract_annotated = 1`) **only after verification** → retry safely (a landed contract is no longer blank, so nothing is written twice) → alert.

* **Terminal outcomes per row** (`fcfs_outcomes` on a real run): `fcfs_contract_verified` · `fcfs_contract_retryable` · `fcfs_contract_needs_review`.
* **Reconcile.** An FCFS add event still open (`0`) or refused (`3`) is closed with `fcfs_contract_verified` **only when MFL already holds exactly the canonical contract for the acquiring franchise's rostered player** — nothing is written to MFL, and a dry run reconciles nothing. This converges the D1 side after a verification read that lagged, an earlier tick, or a hand stamp.
* **Alerts** (`stampHealthAlerts`, commissioner DM, all bookkeeping in `ups_bot_heartbeat`): a blank contract the rule cannot decide → once per distinct batch (24-hour reminder); a retry that outlives ~10 minutes → one escalation per player, recorded **only after the DM actually landed**, and the marker is cleared as soon as the player leaves the retry loop by any route; the **stamp call itself failing** (an unreadable export, a missing cookie, a thrown import) → one DM after ~15 minutes, at most hourly. A missed alert is never recorded as sent.
* **Protections kept:** blank-only writes (a described contract — an owner's MYM, an extension — is never overwritten), no ghost stamps for released players, a BBID with no bid stays needs-input (no default), the circuit breaker.
* **Deployment discriminator:** every response that reaches the stamper carries `fcfs_rule: "canon_a5_2026-09-26"`. A 403 / 500 / 503 refusal before the stamper runs does not.

## 3. The "$1K Per Yr" full-year rule and the canon §C3 WW class — what canon says, and what it does not

* **Canon §A5 / §D1 / §C3 (updated 2026-09-26 on Keith's rulings):** every FCFS acquisition is **$1,000 · one year · `Vet-WW`** (`Rookie-WW` for an NFL rookie), `CL 1| TCV 1K| AAV 1K`; a contract that pays **exactly $1,000 in every contract year** has no weekly and no cumulative earned salary ("Full-year rule" / "1K Per Yr"); a one-year original pure-WW deal of $2K–$4K has earned "not applicable" ("Not applicable" / "nK Per Yr"), cap-free $0 (§C3's worked-table row *"WW under $4K, any time — earned n/a — $0"*). The sub-$5K **penalty** is unchanged ($1K flat while more than one year remains, else $0 — §D1).
* **The label belongs to the contract, never to a TCV cutoff.** Until this hotfix Front Office printed "1K Per Yr" for every contract with TCV ≤ $4K, including a one-year $4K waiver deal. It now prints it only when the worker proves the class (`earned_rule = full_year_sub_5k`) or, before the batch loads, when the exact local check does; a non-class $2K–$4K deal shows its actual per-week rate ($2K → $118, $4K → $235).
* **Class 1 — `classifyFullYearRule`:** `TCV = $1,000 × CL`, CL ≤ 4, the current salary $1,000, **every AAV tier** $1,000, every year token $1,000 **and the year schedule complete when present** (Y-tokens = CL). Missing evidence never proves membership: a dual AAV tier ("AAV 1K, 2K"), a schedule that names fewer years than CL, or a missing CL is *not* in the class.
* **Class 2 — `classifyWwEarnedNa`:** a ONE-YEAR ORIGINAL pure-WW contract (`WW` / `Vet-WW` / `Rookie-WW` — not a WW-MYM), salary ≤ $4,000, TCV = salary, in its final year, not taxi, and not the $1,000-a-year contract (which is class 1). A NULL / blank years-remaining is **unknown, never "final year"** (`Number(null)` is 0 — a fail-open bug the tests caught). A multi-year WW, a WW-MYM and any non-WW deal keep their own earned figure.

`_computeDropPenalty` used to hang a per-week fraction on every sub-$5K contract ($59 = 1/17 of $1,000, $118 = 2/17, $1,118 = a prior $1K year + 118) although the sub-$5K penalty rule never uses earned, and stored it in `ups_drop_events.earned_to_date`. `applyFullYearRule` now returns `earned: null` with `earned_rule: "full_year_sub_5k"` (class 1) or `"ww_earned_na"` (class 2, basis `ww_under_5k_earned_na`); a class-1 contract on the flat multi-year rule carries the explicit basis **`full_year_1k_contract`** (it replaces the legacy `tcv_under_5k_guarantee`, whose penalty had been derived from earned). Taxi / tag / unpriced results and non-members keep their own arithmetic. **The penalty is identical for every week** (tested), so the cap charge does not move; a $1,000 one-year WW deal is in both classes and stays on `ww_under_5k_exempt` under the full-year rule.

**Where `earned_to_date` is still read — the §D2a retirement settlement.** `_d2aSettlement` treats a stored `earned_to_date` as "what the owner actually paid". For a NULL row it derives *actually paid* from the stored contract schedule instead (years served × $1,000): a retired multi-year $1K-a-year player still settles, an unreadable schedule is still "unknown" (never a `$0`).

| Surface | Behaviour |
|---|---|

The `$1K` label is the exact SCHEDULE check (every year exactly $1,000) — the worker's proof when it has one, the local check otherwise (a taxi rookie's row carries no rule, yet its contract is $1,000 a year); the WW label is the worker's `earned_rule` once its row is loaded, with an exact local STATUS check before then (never a TCV cutoff). `EARNED Full-year rule` / `Not applicable` / the figure |

## 4. The corrections (all dry-run-first; nothing applied)

### 4a. `POST /admin/drops/full-year-repair` — the ONE audited, idempotent repair path
Commissioner-key protected. **Dry-run unless the body says `dry_run: false` (a boolean — `"false"`, `0`, `null` and a missing field are all dry runs).** At most 200 actions per call (a larger request is a 400, never a silent truncation); ids must be positive integers; a duplicate id in one request is skipped; malformed JSON is a 400. Five kinds, each on ONE named row, and **a real write requires the dry run's `expect` before-state** (`expectation_required` otherwise; a mismatch is `precondition_failed`). Each change and its audit row (before + after + proof + derivation, `ups_contract_gate_audit`) go in **one atomic D1 batch guarded by `changes() = 1`**, so a concurrent identical request applies once and audits once, and a change can never land unaudited. It never touches MFL or salary adjustments.
* **`clear_full_year_earned`** (class 1) — re-proves class membership from the stored pre-drop contract, refuses taxi / non-dedicated bases / the legacy basis, and is **refused (`conflict_financials_would_change`) unless the canonical flat rule reproduces the stored penalty, exempt flag and posted amount exactly** (fail closed); changes **exactly one column** (`earned_to_date → NULL`) and asserts every other column byte-identical (a violation restores the pre-image and audits `…_ABORTED`).
* **`reconcile_legacy_guarantee_basis`** — a class-1 row on the legacy `tcv_under_5k_guarantee` basis: earned → NULL **and** basis → `full_year_1k_contract`, ONLY when the flat rule gives exactly the stored penalty (else `hold_conflict_penalty_would_change`, earned NOT cleared; unknown years remaining is held too). Two columns; penalty, dead money, guarantee and posted cap untouched.
* **`clear_ww_earned_na`** (class 2, canon §C3) — a one-year pure-WW row of $4K or less on `ww_under_5k_exempt`: earned → NULL and basis → `ww_under_5k_earned_na`; the cap-free $0 penalty, exempt flag and posted state are **proven** unchanged (`conflict_financials_would_change` otherwise).
* **`reprice_unstamped_fcfs_drop`** — an FCFS acquisition dropped before its contract was written: the stored pre-drop contract becomes the canonical one, earned NULL. **Blank-only**, the **latest** add event must be FCFS, `rookie: true` writes `Rookie-WW`, and it is **refused (`conflict_penalty_would_change`) unless the canonical calculation gives exactly the stored penalty and nothing was posted to MFL with another amount**.
* **`close_fcfs_add_event`** (`id` = an `ups_add_events` id) — closes an FCFS add event the stamper's roster re-read can never close. **Path A** (the player was DROPPED before the contract was written — Al-Shaair, add 75): only after that drop's own `reprice_unstamped_fcfs_drop` landed — the stored pre-drop contract must be canonical AND an audit row must name the drop — closes it as `1` with a note that says it is **not roster-verified**. **Path B** (the canonical contract WAS stamped and the owner then converted it — Watson, add 52): the landed `salary_change_log` stamp followed by a landed change whose BEFORE state is that canonical contract (e.g. `/offer-mym`) closes it as `2` ("a described contract is never reverted"). Neither touches MFL or the drop; a re-run is `noop_already_closed` / `not_open`.

## 6. Known limits of the stamper
* The cron looks back 7 days; an FCFS row unresolved for longer keeps its alert history but loses its FCFS identity *for the cron* (the manual route's `days: 30` and the inventory tool still see it).
* The candidate filter treats a `contractYear` of `0` as "MFL described it"; the classifier calls that state `zero` — such rows are listed by the inventory (89, all 2011–2025, each classified — §4c) but never stamped or alerted by the cron.
* A player dropped while his FCFS contract is unresolved is priced `contract_unstamped_needs_review` at drop time; `reprice_unstamped_fcfs_drop` is the after-the-fact cover.
* The blank-contract DM and the post-write verification retry apply to every WW stamp, not only FCFS (a blank contract is never a success).
